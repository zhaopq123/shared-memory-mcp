# 鉴权改造引入的 5 个静默 bug（2026-10-13）

> 全部经真浏览器验证修复。这些 bug 的共同点是**静态检查看不出来** ——
> 单测全绿、curl 探活正常，只有真用浏览器/真部署才暴露。

## 1. 部署假成功：端口被旧进程占着（最隐蔽）

**症状**：deploy 脚本显示「8200 已监听 ✓」、磁盘代码是新的，
但**服务行为还是旧的**。

**根因**：只 kill tmux 会话不够 —— tmux 死了，但它启动的 proot
子进程还活着并占着端口。新进程绑不上端口就自杀，守护循环再重启
再失败 → **无限循环**。

**线索一直在 tmux 日志里**：`[Errno 98] address already in use`。

**修**：deploy 脚本改为**按端口找 PID 并杀掉**（含 `kill -9` 兜底），
并在末尾**自动验证新代码生效**（用新行为当指纹，而不是只看端口通）。

## 2. 面板死锁：静态资源要鉴权 → 登录页自己渲染不出来

**症状**：页面全白，用户无法登录。

**根因**：
```
HTML 返回 → 浏览器请求 panel.js → 被 401 拦掉
→ showLogin() 没定义 → 登录框永不出现
```

`<script src="panel.js">` 由浏览器发起，**不带 Authorization 头**，
首次访问也没 cookie。

**修**：`/`、`panel.js`、`panel.css`、`favicon.ico` 免鉴权。
判据：**贴到公网上，泄露的是「服务长什么样」而不是「库里有什么」**。

## 3. 登录接口被自己拦了

**根因**：`/api/auth/login` 的作用正是「还没有凭据时换凭据」，
逻辑上必须先于鉴权 —— 但它在豁免清单外。

**症状**：登录框提交后永远 401，界面上只表现为「点了没反应」。

## 4. 票据兑换被豁免判断短路

**根因**：`/?login=<ticket>` 在 `/` 免鉴权后被**直接放行**，
根本没走到票据兑换 → cookie 永远设不上。

**修**：把票据兑换移到豁免判断**之前**。

> 3 和 4 是同一个设计错误的两面：**把「换凭据」的逻辑放在了需要凭据的地方。**

## 5. 引用已删除的变量（点按钮就崩）

**根因**：改成 cookie 方案时删掉了全局 `TOKEN`，但「复制分享链接」
那段还在用它 → 点那个按钮抛 `ReferenceError`。

**顺带修**：分享链接不再带凭据（旧版 `?token=<长期凭据>`，
复制给谁就等于把访问权给谁）。

## 新增的回归测试

`tests/test_panel_contract.py`（18 个）—— 钉**契约**而不是实现：

- 静态资源必须免鉴权 **+ 数据接口一个都不能豁免**（对称约束）
- 根路径必须免鉴权 + 登录接口必须免鉴权
- 票据兑换必须真的发生（真跑中间件，看是否 302 + Set-Cookie + httpOnly）
- **JS 引用的 element id 必须在 HTML 里存在**（找不到时 JS 静默失效）
- **不许引用已删除的 TOKEN 变量**
- 分享链接不含凭据

## 可复用的判据

| 场景 | 判据 |
|---|---|
| 哪些路径该免鉴权 | 贴到公网上泄露的是"长什么样"（骨架/样式/逻辑）→ 可豁免；泄露"有什么"（数据）→ 不可豁免 |
| 部署是否真的生效 | **不能只看端口通** —— 要用一个"新代码才有的行为"当指纹 |
| 顺序敏感的逻辑 | 「换凭据」必须早于「校验凭据」；「免鉴权放行」不能短路掉有副作用的处理 |
| JS 静默失效 | 找不到元素/变量时 JS 不报错只不干活 → 必须用真浏览器或契约测试 |
